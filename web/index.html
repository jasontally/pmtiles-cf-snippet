Protomaps Basemap tiles

The whole Protomaps Basemap, zoom 0 to 15, served as one PMTiles archive over plain HTTP. Point any PMTiles client at the URL and it works. There is no API key, no account, and no rate limit.

Use it

  
The archive speaks HTTP range requests, so every PMTiles client can read it.


  
One. Put a map on the page

  
Copy this file. It is the whole example: two script tags, one style URL, one map.


<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Basemap</title>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/maplibre-gl@5/dist/maplibre-gl.css">
  <script src="https://cdn.jsdelivr.net/npm/maplibre-gl@5/dist/maplibre-gl.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/pmtiles@3/dist/pmtiles.js"></script>
  <style>html, body, #map { margin: 0; height: 100%; }</style>
</head>
<body>
  <div id="map"></div>
  <script>
    // Teach MapLibre how to read a PMTiles archive.
    const protocol = new pmtiles.Protocol();
    maplibregl.addProtocol("pmtiles", protocol.tile);

    new maplibregl.Map({
      container: "map",
      style: "https://tiles.jasontally.com/styles/light.json",
      center: [2.35, 48.85],   // Paris
      zoom: 4
    });
  </script>
</body>
</html>


  
Two. Swap the tiles in a style you already have

  

    Every MapLibre style reads its tiles from a source. To use these tiles, change
    that one url. Nothing else in the style changes.
  


  "sources": {
    "protomaps": {
      "type": "vector",
-     "url": "pmtiles://https://demo-bucket.protomaps.com/v4.pmtiles",
+     "url": "pmtiles://https://tiles.jasontally.com/basemap.pmtiles",
      "attribution": "<a href=\"https://www.openstreetmap.org/copyright\">&copy; OpenStreetMap contributors</a>"
    }
  }


  
Or do it in code, which is useful if the style comes from a server you do not control:


// Rewrite every PMTiles source in a style to point at these tiles.
const style = await (await fetch("https://your-server/style.json")).json();

for (const source of Object.values(style.sources)) {
  if (source.url?.startsWith("pmtiles://")) {
    source.url = "pmtiles://https://tiles.jasontally.com/basemap.pmtiles";
  }
}

new maplibregl.Map({ container: "map", style, center: [2.35, 48.85], zoom: 4 });


  

    One thing to check before you swap. This archive is
    Protomaps schema v3. A style written for a different schema
    will load and then draw nothing, because the source layer names do not match.
    The nine layer names are listed below, and so is a ready-made v3 style you can
    copy from.
  


  
Three. About Leaflet

  

    These are vector tiles. Leaflet draws raster tiles, and the
    PMTiles library will refuse this archive in Leaflet with
    archive contains MVT vector tiles, but leafletRasterLayer is for
    displaying raster tiles. That is the library being correct, not a bug.
    Use MapLibre GL as above. If you need Leaflet or a raster image pipeline, you
    need a raster-rendered archive, which this is not.
  


  
Four. Read the archive with the PMTiles library

  
No map, just data. Useful for scripts, tests and anything that is not a picture.


import { PMTiles, FetchSource } from "pmtiles";

const archive = new PMTiles(new FetchSource("https://tiles.jasontally.com/basemap.pmtiles"));

const header = await archive.getHeader();
console.log(header.minZoom, header.maxZoom);        // 0 15
console.log(header.numAddressedTiles);              // 1431655765

const metadata = await archive.getMetadata();
console.log(metadata.name);                          // "Protomaps Basemap"

const tile = await archive.getZxy(3, 4, 2);          // z, x, y
console.log(tile.data.byteLength);

  

    Note the two classes. FetchSource is the byte reader over HTTP, and
    PMTiles is the reader that sits on top of it and understands the
    format. FileSource is the local-file equivalent of
    FetchSource; given a URL string it will not work.
  

  

    The archive is a fixed snapshot and is not being refreshed. If you need current
    OpenStreetMap data, use a source that publishes updates.

What this is not

  
Plain answers, so nothing here surprises you later.


  
    
    
  • 
      There is no service level guarantee. This is a free service
      with no contract behind it. It can be slow, it can go down, and the URL and
      the data can change or disappear without notice. If your product depends on
      it, host your own copy of the tiles or buy a supported plan from someone.
    
    • 
    
  • 
      It is never current to the hour. The copy is rebuilt weekly
      from the newest Protomaps Basemap release, so OpenStreetMap edits made this
      week are not in it yet. Expect a delay of a few days to a week or more behind
      OpenStreetMap.
    
    • 
    
  • 
      No whole-file download. Requests are answered in ranges of at
      most 512 KiB, which is all a PMTiles client ever asks for. Asking for the
      whole 118 GiB in one request returns 416, which is correct.
    
    • 
    
  • 
      Attribution is required. The tiles are derived from
      OpenStreetMap. Keep the attribution line in your style or on your map.
    
    • 
  






  
How fresh is this?

  
The tiles are a copy of the Protomaps Basemap, rebuilt weekly.


  
    
    
  • 
      Rebuilt on Sundays. The rebuild runs between 00:30 and
      07:00 UTC. That is the only window in which the upstream project has never
      published in three years of release history, so a rebuild is not competing
      with a new upstream build halfway through.
    
    • 
    
  • 
      Nothing to do most weeks. A rebuild only happens when the
      upstream project has published something new since the last one. In a week
      with no new upstream release, nothing is rebuilt.
    
    • 
    
  • 
      Which upstream build is in use right now? Use the
      Archive metadata button at the top of this page. It reads
      the archive's own header, so the answer is always current rather than
      something this page could have gone stale about.
    
    • 
    
  • 
      A rebuild is not instantaneous. It is thirteen separate
      rebuilds spread over about six and a half hours, one at a time. For most of
      that window the copy is a mix of two upstream builds. A tile you request
      during it may come from the newer build rather than the one the reader
      advertised, which shows as a tile from the wrong place, not as a broken
      map.
    
    • 
    
  • 
      A rebuild can be missed. It is a best-effort job, not a
      guarantee. If one step fails, the rest of the copy stays on the previous
      upstream build. It is still a working map.
